# RAG 知识库问答 · 需求说明

> W05 交付物。本文件定义「做什么、不做什么、怎么算做完」，是 W06 起所有实现与验收的依据。
> 决策日期：2026-11-23｜状态：v1，随 W06–W12 实验结论迭代

## 1. 问题与用户

**用户**：需要查阅技术手册的开发者（第一用户是我自己）。

**现状痛点**：一本几百页的开发手册，`Ctrl+F` 只能做关键词精确匹配。
问「集合初始化时为什么要指定初始容量」这类语义问题，得翻好几处才能拼出答案，
而且没法确认自己找到的是不是最新、最完整的那一段。

**目标**：用自然语言提问，直接得到**带出处**的答案；答不了就明确说答不了。

## 2. 语料范围

| 项 | 决策 |
|---|---|
| 文件类型 | 文本型 PDF（有可提取文字层） |
| 首批语料 | `RAG/pdf/AlibabaJavaDevelopmentManual.pdf`（实测 39 页，38 页有文字层，第 1 页为封面） |
| 规模 | 先单文档跑通，W07 起支持多文档 |
| 语言 | 中文为主 |

## 3. 做什么（功能范围）

1. **PDF 解析**：提取文字，保留页码、章节标题等元数据，生成可追溯的文档块
2. **切块**：按语义边界切分（优先在段落/标题处断开），块与块之间允许必要重叠
3. **稳定 ID**：同一份文档重复导入，块 ID 不变，不产生重复索引
4. **检索**：给定问题返回最相关的若干块，附来源信息
5. **回答**：基于检索到的块生成答案，**每个结论都要能指回具体块**
6. **拒答**：检索不到依据时明确说「资料中未找到」，不编造
7. **接口**：FastAPI 提供问答接口，含超时、重试与日志
8. **评测**：固定题库 + 自动评测脚本，能量化每次改动的效果

## 4. 不做什么（明确边界）

| 不支持 | 原因 / 处置 |
|---|---|
| 扫描件、图片型 PDF | 无文字层，需 OCR；列为已知边界，不引入 OCR 依赖 |
| 图片内文字、图表中的数据 | 解析只取文字层 |
| 表格跨页结构还原 | 只提取单元格文本，不保证表格结构与原页一致 |
| 手写体、公式排版 | 不在语料范围内 |
| 多轮对话与上下文记忆 | v1 只做单轮问答 |
| 用户权限隔离 | 留到 W15，v1 单用户 |
| 增量更新已有文档 | v1 只保证重复导入幂等，不做局部更新 |

## 5. 验收标准

### 5.1 解析与切块（W06）

- 每块都能回溯到「文件名 + 页码 + 原文片段」
- 页眉页脚、目录等重复噪声有明确处理方式
- 扫描件输入时给出清晰报错，而不是静默产出空块
- 首批 15～20 道评测题，标注参考答案与出处页码

### 5.2 检索与回答（W07–W08）

- 问答结果必带来源，来源必须是真实存在的块（不得指向不存在的页码）
- 无答案类问题拒答率达标，不出现编造
- 重复导入同一份 PDF，索引条数不增加

### 5.3 评测（W09–W12）

- 题库冻结，调优集与保留验收集分开
- 每次改动有对照：检索命中率、回答支持率、误拒答率
- 能区分错误来自解析、检索还是生成

## 6. 非功能要求

| 项 | 目标 |
|---|---|
| 单次问答延迟 | P95 < 10s（含检索 + 生成） |
| 成本 | 记录每千 token 成本，优先利用上下文缓存 |
| 可追溯 | 任何一条回答都能定位到块 ID 与页码 |
| 可复现 | 固定依赖版本，一条命令完成索引重建 |

## 7. 技术约束

- Python 3.11（沿用 `ai_app` 环境）
- 解析：PyMuPDF 或 pdfplumber（W06 对比后定）
- 向量库：Chroma（环境已有）
- 生成模型：DeepSeek `deepseek-chat`（复用 `statge/practice/llm_api/config.py` 的读取方式）

## 8. 已知风险

| 风险 | 影响 | 初步对策 |
|---|---|---|
| 页眉页脚在每页重复 | 检索命中大量无意义块 | 按出现频率剔除高频重复行 |
| 章节标题与正文被切散 | 块缺少上下文，答案断章取义 | 切块时把所属标题拼进块前缀 |
| 表格被抽成乱序文本 | 数值类问题答错 | 评测题避免依赖表格结构；在文档写明局限 |
| 中文按字符切导致语义割裂 | 检索召回质量下降 | W06 对比字符/句/段三种切法的实际效果 |
